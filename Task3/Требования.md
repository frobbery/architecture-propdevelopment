## Список требований, которым должны удовлетворить внешние интеграции

### Требования к безопасности
- Биометрия, видео с изображением людей и номера машин относятся к персональным данным, утечка которых может привести к серьезным законодательным и репутационным последствиям, поэтому при хранении и передаче данных необходимо обеспечить их шифрование
- Допущенная биометрия и номера машин должны храниться только во внутренней системе
- Нельзя допустить, чтобы запросы к вендору были поделаны и злоумышленник смог бы открыть дверь/поднять шлагбаум, и, аналогично, нельзя чтобы злоумышленник смог подделать запросы к внутреннему АПИ, для проверки допустимых данных, поэтому следует использовать двухстороннюю аутентификацию и авторизацию
- Вендору должны быть доступны только обезличенные данные, такие как id устройства
- Персональная информация в логах должна маскироваться
- Вендору должен быть доступен только минимальный необходимый набор данных

### Протоколы аутентификации и авторизации
- Для аутентификации должен использоваться mTLS на стороне вендора и системы
- Для аутентификации должен использоваться OAuth 2.0
- Для первоначальной регистрации устройства на стороне вендора должен использоваться API key, после чего для каждого устройства должен генерироваться отдельный accessToken и refreshToken, используемые для выполнения действий на конкретных устройствах
- accessToken и refreshToken, создаваемые вендором, будут храниться в внутренней системе зашифрованными
- refreshToken ограничен по времени действия, и при каждом рефреше обновляется
- Для аутентификации запросов вендора в внутренней системе используется API key 

### Описания взаимодействия между внутренней системой и вендором

Все устройства необходимо первоначально зарегистрировать во внутренней системе и системе вендора, что описано в пункте выше

#### Интеграция с интеллектуальным домофоном

- При вызове домофона, АПИ вендора сначала проверяет разрешен ли доступ в дом для пользователя
- Для этого АПИ вендора посылает во внутренний АПИ данные биометрии и id устройства, зашифрованные mTLS
- Внутренний АПИ проверяет совпадение разрешенной биометрии для данного устройства и возвращает допуск
- Если допуск запрещен, АПИ вендора посылает уведомление о звонке, после чего внутрення система отображает его пользователю и пользователь может просмотреть трансляцию видео с домофона
- Для открытия домофона, внутренняя система посылает запрос, зашифрованный mTLS, с id и accessToken устройства

#### Интеграция с шлагбаумом

- АПИ шлагбаума посылает распознанный номер и id устройства, для проверки разрешения на въезд, зашифрованные mTLS
- Внутренняя система проверяет совпадение номера с разрешенными для устройства и возвращает ответ
- Для поднятия шлагбаума, внутренняя система посылает запрос, зашифрованный mTLS, с id и accessToken устройства
